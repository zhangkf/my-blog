用简单的 Markdown 文件夹和一个 CLAUDE.md 索引文件地图，搭出你的 AI 原生第二大脑。

「第二大脑」这个词听起来有点装，但说到底，它就是几个文件夹里的几个文本文件，由一个索引文件统一管理，指引 AI 去哪找东西。不需要 Obsidian，不需要复杂数据库，不需要臃肿的应用——只有静静躺在你硬盘上的纯 Markdown。

这篇教程从零搭起这套架构：组织目录结构、写你的路线图（CLAUDE.md 文件）、定命名规则，并讲清楚智能体到底是怎么解析这一切的。做完的时候，你会有一套可以复制、可以立刻往里填东西的可靠系统。

**简短版答案**

「第二大脑」无非是一组平铺的 .md 文件，按简单的文件夹组织，根目录放一个 CLAUDE.md 当索引。它是一只罗盘，告诉智能体信息在哪、文件怎么组织、读取的规矩是什么。黄金法则：**一个文件一个主题**。CLAUDE.md 就是智能体在你的知识里导航用的地图。你不需要专门的笔记应用。

**你需要什么**

- 一个能读项目目录的 AI 智能体（比如 Claude Code 或同类）。
- 任何文本编辑器。这些都是标准 .md 文件，什么工具都能打开。
- 五分钟。搭文件夹够了。内容可以边用边填，不必先把全部数据搬进来。
注意：全程没有安装脚本，没有复杂配置。这是一套文件结构加一个索引，不是软件产品。

**原则：平铺文件胜过应用**

「去下载 Obsidian」「去建一个漂亮的 Notion 数据库」——这个本能通常是个陷阱。应用会带来自己的私有格式、存储逻辑和界面，这些常常给 AI 制造摩擦。智能体最好干活的场景，是直接读你磁盘上一个简单的文本文件，中间没有任何隔层。

所以这里的地基是平铺的 Markdown 文件。「平铺」的意思是：纯文本加标准格式（标题、列表），没有嵌套数据库，没有私有链接格式。任何地方都能访问，人和 AI 都能读。这不是为简单而做的牺牲，而是战略优势：格式越干净，横在你知识和智能体之间的墙就越少。

三个核心文件夹覆盖几乎全部场景：

- **notes/**：事实和专题条目。学到了什么，提炼进来。一个文件一个主题。
- **people/**：联系人或公司的卡片：他们是谁、会议摘要、关键细节。一个人一个文件。
- **projects/**：项目状态：正在做什么、停在了哪、下一步是什么。
另外，用根目录的文件存放你工作流的元信息：MEMORY.md（长期核心信息）、LEARNINGS.md（经验教训）、decisions.md（你的决策审计日志）。

**CLAUDE.md，那张地图**

这是大脑的神经系统。文件夹只是仓库；要让它们可用，你需要一张地图。根目录的 CLAUDE.md 告诉智能体怎么解读你的结构。

为什么是 CLAUDE.md？如果你用 Claude Code，它启动时会自动把这个文件加载进系统提示词。你不必提示智能体「去读地图」——在你问第一句话之前，它已经知道了游戏规则。

**进阶技巧：用好 @ 连接**

更进一步的玩法：你的 CLAUDE.md 可以用 @ 路径直接引用核心文件。把 @MEMORY.md 或 @decisions.md 加进地图，智能体会始终把这些高层上下文放在活动记忆里。克制使用——只放真正需要持续在焦距里的东西。

**命名规则：纪律就是一切**

「一文件一主题」这条规则，决定大多数系统的成败。

- **一文件一主题。**别把几个不相干的点「倒」进一个 notes.md。内容是税务政策，就建 tax-policy.md。
- **主题即文件名。**文件名说清内容。用 ivan-petrov.md，别用 note-12.md。
- **统一风格。**坚持小写加连字符，避免歧义。
**智能体是怎么读它的**

你发起会话，智能体摄入 CLAUDE.md。你提问，它用地图定位正确的文件，解析，综合出答案——并附上出处。信息不在里面，它就报告「找不到」，而不是编一个。你唯一的责任是维护干净的结构；检索交给智能体。

**常见问答**

- 地图必须叫 CLAUDE.md 吗？用 Claude Code 的话，是，它是自动加载的。换其他智能体，就用 README.md 或一个等效的根目录索引。
- 起步该建几个文件夹？保持简单。三个主文件夹加根目录那几个文件就够了。等某个主题大到值得独立目录时再扩。
- 旧笔记必须全部搬进来吗？不用。现在把骨架搭好，边用边迁移、边新建。
**最后一句**

你的第二大脑就是一组平铺的 .md 文件、一条严格的「一主题一文件」纪律，和一张给智能体指路的 CLAUDE.md 地图。忘掉复杂的软件，把你磁盘上的文本文件理整齐就行。把时间投资在地图上——一份清晰的 CLAUDE.md，就是「一团乱麻」和「一个能用的 AI 助手」之间的全部差别。
