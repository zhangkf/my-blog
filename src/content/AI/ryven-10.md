你今年读了几千页。文章、帖子、文档、访谈记录。现在试着想出一篇你今天就能用上的。

很难，对吧。你读过的所有东西，进了标签页、书签和聊天窗口，它们互相之间从来没有任何连接。下周你还会读更多，而这些新读的东西照样不和其余任何东西说话。

一个晚上，事情可以这样改变：你建一个文件夹，所有你存进去的东西都会被读、被总结、链接到你已有的笔记，然后被保留下来。你问 Claude 一个问题，它从这全部积累里回答你。你睡觉的时候，它归档新材料。第二天早上打开它，它已经知道你是谁、你在做什么。

只要会复制粘贴，你就搭得起来。前五步大约 20 分钟，做完你就有一个能运转的大脑。第六到第十步让它越来越聪明。

这个结构来自 Andrej Karpathy 2026 年 4 月发布的 LLM Wiki 模式（GitHub 上一个简短的 markdown 文件）。核心想法：别再让模型在每次提问时去翻你的原始笔记。让它从你的源材料里一次性建好一座 wiki，保持整洁，然后从 wiki 里回答。

收藏这篇。搭的时候你会想让它开着。

## 你需要什么

- 一台电脑（Windows 或 Mac）
- Claude Pro 或 Max（两个档位都包含 Claude Code）
- 一份你想保留的东西：一篇文章、一份访谈记录、一条随手笔记
- 大约 20 分钟，用来拿到第一个成果
## 开工前先知道两件事

**Claude 读什么，什么就会被发给模型。** 它只能根据打开过的文件回答问题，而打开一个文件，就意味着内容被模型处理。保密材料不要放进 raw/，除非你的套餐和工作单位的规定允许。

**用量额度是共享的。** Pro 和 Max 的额度在 Claude 和 Claude Code 之间合并计算。一次性摄入几百个文件会飞快烧掉额度，所以从五到十个文件起步。

## 你在搭什么

两个工具，两种分工。

**Obsidian 是你看的窗口。** 一款免费笔记应用，所有内容都以纯文本文件的形式存在你自己的电脑上。笔记之间用双括号链接，这些链接会画出一张你的想法如何连接的地图。

**Claude Code 是干活的。** 它待在同一个文件夹里，读文件、写新文件、维持秩序。

文件夹有三个房间和一本规则书：

- **raw/ 放你的源材料。** Claude 读它们，永远不改动它们。
- **wiki/ 放 Claude 从源材料里建出来的东西**：总结页、概念页，互相链接。你负责读，Claude 负责写。
- **output/ 放完成品**，从 wiki 里产出，而不是从记忆里。
- **CLAUDE.md 是规则书**：你是谁、你在建什么、这个文件夹怎么运转。Claude 在每次会话开始时加载它。
需要 Obsidian 吗？不需要——Claude 对任何文件夹都能干活。Obsidian 是窗户和图谱视图，没有它也搭得起来，但你会失去那张地图。

一切都是纯文本，所以没有任何东西被锁死。明年你把另一个模型指向同一个文件夹，它照样能用。这个大脑是你的。

## 十步搭建

**第一步：装 Claude Desktop（3 分钟）**

打开 claude.com/download，装应用，登录。打开 Code 标签页。这是能读写你电脑上文件的那个版本。

结果：Code 标签页已打开。

**第二步：建库（5 分钟）**

从 obsidian.md 下载 Obsidian 并打开。点 Create new vault（新建库），命名为 brain，选好位置，确认。

在左侧边栏的空白处右键，选 New folder（新建文件夹），建三个文件夹：raw、wiki、output。

快速试一下核心机制：新建一条笔记，打一句话，然后输入 [[goals]]。这个词现在是一个链接了。Claude 很快就会成百地制造这种链接。

结果：一个带三个文件夹的空库。

**第三步：在 Claude 里打开这个文件夹（2 分钟）**

库只是一个文件夹，所以 Claude Code 可以直接在里面工作，不需要任何插件。

在 Code 标签页里，选你的 brain 文件夹作为工作文件夹，开始会话。如果它问你是否信任这个文件夹，选是。然后输入：

```
列出这里的文件夹，告诉我每个是干什么用的。
```

结果：Claude 报出 raw、wiki 和 output。让 Obsidian 在旁边开着。Claude 写的任何东西，几秒之内就会出现在那边。

**第四步：告诉它你是谁（5 分钟）**

Claude Code 每次会话都从一片空白的记忆开始。它认识你的方式是一个叫 CLAUDE.md 的文件，每次都从工作文件夹加载。别自己写，让 Claude 采访你：

```
帮我搭建第二大脑。一次一个问题地采访我：我是谁、我做什么；我今年在建什么；我希望你用什么方式跟我沟通；我希望这个大脑帮我产出什么。每个答案等你收到再问下一个。

然后在这个文件夹里写一份 CLAUDE.md，包含这些小节：关于我、当前项目、怎么跟我沟通、这个文件夹怎么运转（raw/ 是源材料，永远不改；wiki/ 是你写的页面，保持互相链接；output/ 是从 wiki/ 建出来的完成品），以及 Wiki 规则（一页一个想法，用[[双括号]]链接，保持 wiki/index.md 里每一页都有一行说明）。全文不超过 200 行。
```

回答的时候，就当你在给一位新搭档交代工作。具体比漂亮重要。

结果：库里多了一份 CLAUDE.md。从今往后，每次会话开始时 Claude 已经认识你。

**第五步：喂第一份源（5 分钟）**

大脑开始存在的时刻。

把一份你想保留的东西存成文本或 markdown 文件放进 raw/，然后粘贴：

```
摄入 raw/ 里的新文件。在 wiki/ 写一页总结。为它涉及的每一个概念、人物和项目创建或更新页面，全部用[[双括号]]互相链接，并把新页面加进 wiki/index.md。不要改动 raw/ 里的任何东西。列出你创建或修改了什么。
```

切到 Obsidian，打开图谱视图。

不知道先喂什么？从这里选：

- 同一个主题下你存过的十篇最好的文章
- 你最近三次通话或会议的记录
- 你自己发过的帖子、写过的随笔或笔记
- 一份你反复回去看的项目文档
结果：第一批互相链接的页面出现在地图上，其中一些五分钟前还不存在。你现在有一个能运转的第二大脑了。下面的内容让它越来越锋利。

**第六步：问它问题**

现在用起来。问一个横跨多份源材料的问题：

```
只用 wiki/，我收集到的关于[主题]的三条最佳论据是什么？说出每条来自哪一页。如果 wiki 没有覆盖其中某部分，直说。
```

最后一句很关键。它防止 Claude 用自己的通用知识填空，再冒充是你的积累。

答案好的时候，留住它：

```
把这个回答存成 wiki/ 里的新页面，链接到它用到的页面，并加进索引。
```

结果：你的问题变成页面，这些页面又回答你接下来的问题。这就是复利。

**第七步：一次只做一个项目**

一座大库适合思考，不适合专注。给每个项目自己的房间：

```
创建 wiki/youtube-channel/ 文件夹，配一份它自己的 CLAUDE.md：这个项目是什么、唯一的目标、你应该怎么帮忙、对它最重要的 wiki 页面是哪些。需要细节就采访我。
```

把 youtube-channel 换成任何项目。Claude Code 启动时会从工作文件夹和它上层的文件夹加载 CLAUDE.md，进入某个子文件夹干活时再加载那里的 CLAUDE.md。项目的规则只在你做那个项目时精确生效。

结果：一个自带说明书的房间。

**第八步：把重复的事存成技能**

任何你做过不止两次的事，都应该变成一个技能——存下来的工作流程，Claude 收到指令就跑。Anthropic 自己的建议就是：把多步骤流程从 CLAUDE.md 挪进技能，让规则书保持简短。

```
把我重复做的一个流程变成可复用的技能。我的做法是：[步骤和一个例子]。把它做成一个名字清晰、带一句何时该用它说明的技能。
```

好的第一批候选：摄入一个 YouTube 字幕、把三页 wiki 合成一篇文章初稿、跑一次周五复盘。

结果：一条指令顶替十分钟的例行操作。

**第九步：接入活数据（日历）**

笔记只是半个大脑。另一半是今天正在发生的事。

Claude 可以通过一个叫 workspace-mcp 的 MCP 服务器读你的 Google 日历。一个实话实说的弯路：它需要 Google Cloud 的 OAuth 凭据。你建一个项目、启用 Google Calendar API、创建一个 OAuth 客户端，然后把两个值设置好，再添加服务器：

```
export GOOGLE_OAUTH_CLIENT_ID="your-client-id"
export GOOGLE_OAUTH_CLIENT_SECRET="your-client-secret"
claude mcp add google-workspace uvx workspace-mcp --tools calendar
```

首次使用会弹出 Google 登录，批准它。然后试：

```
读我今天的日历。每个会给 wiki/meetings.md 加一行：决定了什么、我欠谁什么。没有明确下一步的会议，标记出来。
```

这是全篇最长的一段配置，也是唯一一个跳过完全不损失其他部分的步骤。

结果：你的一天自动喂进大脑。

**第十步：挂上自动驾驶**

定时任务按点启动全新的 Claude 会话。大脑趁你睡觉自己归档，靠的就是这个。

在 Code 标签页点 Scheduled（定时），再点 New task（新任务）（如果出菜单选 Set up manually 手动设置）。填：

- 名称：nightly-brain
- 指令：
```
检查 raw/ 里还没摄入的文件。逐一摄入：写 wiki 总结、更新相关页面、链接一切、加进 wiki/index.md。永远不要改 raw/。然后写 output/daily-log.md，三行内容：你加了什么、改了什么、哪些需要我决定。
```

- 仅在此电脑上：开（在高级设置里）
- 本地文件夹：你的 brain 文件夹
- 触发：每天，你选的时间
点 Create（创建），然后立刻点一次 Run now（立即运行）。留意权限弹窗，任务需要什么就选「始终允许」——否则夜里的运行会卡在等一个不会有人来给的批准上。

两个要提前知道的事实：本地任务只在桌面应用开着、电脑醒着的时候触发，机器睡过时间点的那次运行会被跳过。想让它通宵跑，去 设置 → 这台电脑 → 系统 里打开「保持电脑唤醒」。云上的定时任务看不见你的本地库，所以用本地这种。

再加一个每周任务做保养：

```
检查 wiki/。列出互相矛盾的页面、没有任何链接的页面、在多处出现却没有自己页面的想法、以及 raw/ 里没有出处的论断。什么都别改。给我清单，每条附一个修改建议。
```

结果：大脑自己摄入、自己体检。你早上醒来有一份日志。

## 四种坏法（和修法）

- **动手改 raw/。** 源材料必须原封不动，把这条规则写进 CLAUDE.md。
- **一份巨型 CLAUDE.md。** Anthropic 的文档建议 200 行以内。流程挪进技能。
- **开放式提问。** 提示词里保住「只用 wiki/」，否则 Claude 会拿通用知识填空。
- **不保养。** 只长不体检的 wiki 会自己跟自己打架，让每周体检一直跑着。
## 一条保护它的规则：权限，而不是承诺

在 CLAUDE.md 里写「永远不要删除文件」，那是一个请求。Anthropic 的文档说得很直白：CLAUDE.md 是上下文，不是强制执行的配置。要拦住某个动作、不管 Claude 自己怎么决定都拦住，得用权限设置或 PreToolUse 钩子。

所以：给文件夹做好备份（一份同步副本或一个 git 仓库，让任何一次糟糕的改动离撤销只差一步）、给定时任务用能跑起来的最窄权限档、如果你启用 Obsidian 的 MCP 服务器，要知道它带一个删除工具，批准之前想清楚。

## 不想自己搭：两个值得认识的仓库

如果你想从一个打包好的东西开始，有两个开源项目建在同一套想法上。

**claude-obsidian**（作者 AgriciDaniel）是一个自组织的第二大脑，配 Obsidian 和 Claude Code，基于 Karpathy 的 LLM Wiki 模式。它作为 Claude Code 插件运行，带 /claude-obsidian:wiki-ingest 和 /claude-obsidian:wiki-query 这类命令。安装比上面的步骤更费手，先读它的 README。

**obsidian-second-brain**（作者 eugeniughelbur）是一个 Claude Code 技能，带 43 条斜杠命令。它也能配 Codex CLI、Gemini CLI 和 OpenCode 用，所以你不被绑死在一个工具上。它的 Google 日历命令只在 Claude Code 里能用。

两个都是文本文件加脚本。克隆一个，然后改成你自己的。

## 30 天计划

一天一件小事，胜过一个宏大的周末。

**第 1 周：搭。** 第 1 天：第一到五步，喂一份源。第 2 天：再加五份。第 3 天：问三个问题，存下两个最好的回答。第 4 天：建第一个项目房间。第 5 天：存第一个技能。第 6 天：挂上夜间任务。第 7 天：跑一次每周体检。

**第 2 周：喂。** 每天三份新源。每天一个问题，好回答就存。

**第 3 周：连。** 加日历那步和第二个项目房间。只靠 wiki（不靠记忆）在 output/ 里写出一篇真正的东西。

**第 4 周：紧。** 每周体检跑两次。合并弱页面、修掉矛盾，然后打开图谱，看看长出了什么。

## 接下来会发生什么

第一天，你拿到第一批互相链接的页面。一周内，十份源进去，你就能问横跨全部的问题。一个月内，打开图谱，你会看到自己没规划过的簇，以及把几个月前存的东西连在一起的页面——你早忘了自己知道。

在这之前，标签页一关，Claude 就忘了你。在这之后，每次会话开始，Claude 都认识你、你的项目和你存过的一切。搜索找到你存的。编译建立你理解的。

读完这篇花了十分钟。前五步只要二十分钟。这两件事里只有一件会改变你的工作方式。现在就挑一份源，摄入它，问一个问题，把答案存下来。这篇指南里其余的一切，都是这个循环的重复。

收藏这篇指南；想看更多这类配置，关注我。我写 AI、Claude 和真正跑得起来的系统。

## 尾注：我核实过什么

wiki 结构（raw 源材料、模型写的 wiki、一个 schema 文件，以及摄入、查询、检查三种操作）依据 Karpathy 2026 年 4 月 gist 的公开摘要。CLAUDE.md 的加载方式、200 行建议、「上下文而非强制配置」的提法和 Desktop 定时任务的细节，来自 Anthropic 的 Claude Code 文档（2026 年 10 月 27 日读）。mcp-obsidian、workspace-mcp（包括 OAuth 要求）和两个仓库都依据其公开页面描述。Claude Code 包含在 Pro 和 Max 里，依据 Anthropic 的支持文章。时间估算是我自己的。我没有把这个流程从头到尾跑过一遍，菜单名称可能因应用版本而不同。
